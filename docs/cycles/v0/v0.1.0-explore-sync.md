## 1. 범위

코드가 없는 레포에 Bun · Hono · Svelte 뼈대가 서고, 사용자가 등록한 GitHub 레포의 이슈가 로컬 sqlite로 들어와 화면 목록에 보인다.

### 1.1 뼈대 — #1

- 무엇을: 코드 0줄 → Bun 위에 Hono 서버와 Svelte 5 프론트가 붙어 `bun run dev`로 `localhost:4747`에 헤더만 있는 빈 대시보드가 뜨고, `bun run start`로도 같은 화면이 뜨며, `bun test`가 살아 있다.
- 어떻게: package.json 하나. `server/`(Hono · bun:sqlite)와 `web/`(Svelte + Vite)로 나눈다. dev는 Vite 개발 서버와 Hono를 함께 띄우고 `/api`를 프록시한다. start는 `vite build` 뒤 Hono가 정적 파일을 서빙한다. 스크립트는 `dev` `start` `test` `check` 넷.
- 끝(SC-1): `bun test` 통과(테스트 1개 이상) · `bun run check` 에러 0 · `bun run dev`와 `bun run start` 각각 `localhost:4747`에 헤더 있는 빈 화면 — 자동 둘은 이 항목이 `CLAUDE.md` cycle 절 검증 줄에 새로 적는다. 화면 둘은 사용자 육안.
- 왜 이렇게: `docs/design.md` 스택 · 실행 형태 그대로. 워크스페이스(모노레포)는 쓰지 않는다. 로컬 앱 하나에 패키지 둘은 의존성 관리만 늘린다.

### 1.2 동기화 — #2

- 무엇을: 로컬에 데이터 없음 → `~/.cadence/cadence.sqlite`가 생기고 `repos` · `issues` 테이블이 마이그레이션으로 만들어진다. API로 `owner/name`을 등록하면 `gh issue list --json`으로 이슈가 `issues`에 들어간다. 다시 가져오면 같은 `(repo_id, number)`가 갱신되고 닫힌 이슈는 `state`만 바뀌고 행은 남는다.
- 어떻게: 세 층. `server/db/`는 bun:sqlite 열기와 `migrations/001_*.sql`부터 번호순 적용, 적용 이력 테이블. `server/github/`는 `gh` 자식 프로세스 호출을 함수 하나로 감싸고 테스트에서 바꿔 끼울 수 있게 한다. `server/sync/`는 레포 등록 · 가져오기 · upsert. 라우트는 `POST /api/repos` · `POST /api/sync` · `GET /api/issues` 셋.
- 끝(SC-2): `bun test`에서 마이그레이션이 빈 DB에 테이블을 만들고 두 번 돌려도 같으며, 가짜 gh 응답으로 가져오기 → upsert → 재가져오기(하나 닫힘)까지 `issues` 행이 기대와 같다 — `bun test`. 실제 `gh`로 `SpiritFlag/cadence`를 등록해 이슈 8건이 sqlite에 들어가는 것은 사용자 육안(`GET /api/issues` 응답).
- 왜 이렇게: gh 호출을 주입 가능하게 해야 테스트가 네트워크 없이 돈다. 마이그레이션은 `docs/design.md` 결정. `gh issue list`는 `--state all --limit 1000`으로 가져온다. 닫힌 이슈 행을 남기려면 닫힘을 알아야 한다. `issues.labels`는 라벨 이름 배열 JSON. 지금 필요한 것은 `p1`~`hold` 판별뿐이다.

### 1.3 목록 화면 — #3

- 무엇을: 빈 껍데기 → 상단에 등록된 레포 칩과 `owner/name` 입력칸과 새로고침 버튼. 왼쪽 영역에 열린 이슈가 번호 · 제목 · 라벨 뱃지로 목록. 클릭하면 아래 상세 패널에 제목 · 라벨 · 본문(텍스트). 새로고침은 `POST /api/sync` 뒤 목록을 다시 읽는다.
- 어떻게: Svelte 5 룬 기반 상태 하나(`repos` · `issues` · `selected`)를 `web/src/lib/store.svelte.ts`에 두고, 컴포넌트는 `Header` · `IssueList` · `IssueDetail` 셋. API 호출은 `web/src/lib/api.ts` 한 파일. 레이아웃 뼈대(좌 · 우 · 하 3구역)는 `docs/design.md` 화면대로 지금 잡고, 우측 패키지 영역은 빈 칸. 그래프 자리는 이번엔 목록이 차지한다.
- 끝(SC-3): 사용자 육안 — `bun run dev`에서 ① `SpiritFlag/cadence` 추가하면 칩이 생기고 ② 이슈 8건이 라벨 뱃지와 함께 목록에 보이고 ③ 하나를 클릭하면 아래에 본문이 보이고 ④ 새로고침을 누르면 목록이 다시 그려진다. 자동은 `bun run check` 에러 0.
- 왜 이렇게: 프론트 테스트 러너는 이번 사이클에 넣지 않는다. 화면 셋에 도구를 하나 더 붙이는 것은 과하다. 로직은 전부 서버에 있어 `bun test`가 덮고 화면은 육안. 그래프 · 제안 화면이 복잡해지면 그때 정한다.

제외: 의존 선(#4) · 그래프(#5). 목록을 만들다 선을 긋고 싶어져도 하지 않는다.

| 배치 | 정한 것 | 이유 |
|---|---|---|
| start | 프론트 테스트 러너를 이번 사이클에 두지 않는다 | 화면 셋에 도구 하나 더는 과하다. 로직은 서버에 있어 `bun test`가 덮는다 |
| B-1 | TypeScript를 `~6`으로 고정한다 | svelte-check 4.7이 TypeScript 7을 아직 단독으로 지원하지 않는다 |
| B-2 | 마이그레이션 이력은 `_migrations(name)` 테이블, 파일은 이름순 · 각각 트랜잭션 | 적용된 파일을 건너뛰어야 두 번 돌려도 같다 |
| B-2 | sqlite는 WAL · foreign_keys on | 로컬 단일 사용자라 WAL이 안전하고 빠르다. `deps`가 올 때 cascade가 필요하다 |
| B-3 | `createApp({db, source})`로 DB와 이슈 원천을 주입한다 | 테스트가 `:memory:`와 가짜 gh로 네트워크 없이 돈다 |
| B-3 | 시각은 전부 UTC ISO 문자열 | sqlite `datetime('now')`와 gh의 `updatedAt`이 둘 다 UTC라 섞이지 않는다 |
| B-4 | 프론트 타입은 `server/sync`에서 type-only import한다 | 정본이 하나여야 한다. 타입만 가져와 번들에는 안 들어간다 |
| B-4 | 레포 추가는 등록과 동시에 동기화한다 | 추가하고 새로고침을 또 누르게 하면 두 단계다 |
| B-1 | dev는 Vite 4747 · Hono 4748(`CADENCE_PORT`), start는 Hono 4747 | 브라우저 주소가 두 모드에서 같아야 한다. `/api`는 Vite가 프록시한다 |
