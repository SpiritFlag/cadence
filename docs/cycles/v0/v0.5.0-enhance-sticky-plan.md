## 1. 범위

오른쪽 칸 패키지 위에 고른 레포의 지나간 마일스톤이 순서대로 보이고, 제안은 5순위까지만 나오며 직전 제안의 안 뽑힌 패키지 순서를 지킨다. 끼어들거나 합류하거나 선 때문에 옮긴 패키지에는 표시가 붙는다.

### 1.1 지나간 마일스톤이 패키지 위에 보인다 — #13

- 무엇을: cadence는 마일스톤을 모른다. 이슈를 가져올 때 마일스톤 칸을 받지 않고 저장할 곳도 없다 → [새로고침]이 레포마다 마일스톤(제목 · 상태 · 만든 날 · 닫은 날)과 이슈마다 붙은 마일스톤 번호를 받아 sqlite에 저장한다. 오른쪽 칸 "다음 패키지" 위에 고른 레포의 마일스톤이 `v0.4.0 · 닫힘 · 09-14 · #9 #10` 모양으로 한 줄씩 보인다. 위가 오래된 것, 아래로 갈수록 최근이고 진행 중인 것이 맨 아래라 바로 밑 패키지로 이어진다. 기본은 진행 중인 마일스톤 전부와 최근에 닫힌 것 1개. 맨 위 [더보기]를 누를 때마다 더 오래된 것 5개가 위에 붙는다. 줄의 이슈 번호는 열린 이슈만 눌러서 선택되고 닫힌 이슈는 글자만 보인다. **`docs/SPEC.md` 동기화 절(가져오는 것)과 화면 절(오른쪽 칸 구성)이 바뀐다.**
- 어떻게: 동기화는 이슈 가져오기에 `milestone` 칸을 더하고 레포마다 `gh api repos/{o}/{n}/milestones?state=all`을 한 번 더 부른다. 마이그레이션 005로 `milestones` 테이블과 이슈의 마일스톤 번호 열을 만든다. `GET /api/milestones?repo=`가 마일스톤마다 붙은 이슈 번호(닫힌 이슈 포함)와 함께 목록을 준다. 화면은 새 컴포넌트를 패키지 칸 위에 붙이고 [더보기]는 받은 목록을 브라우저에서 자른다.
- 끝(SC-1): cadence 레포에서 [새로고침]을 누르면 패키지 위에 닫힌 v0.4.0(09-14 · #9 #10)과 진행 중 v0.5.0 두 줄이 보이고, [더보기]를 누르면 v0.3.0 · v0.2.0 · v0.1.0이 위에 붙는다 — `bun test`(마일스톤 upsert · 이슈의 마일스톤 번호 · 레포 필터) · `bun run dev` 사용자 육안.
- 왜 이렇게: 이슈에서 거꾸로 모으면 이슈 없는 마일스톤이 빠지고 상태 · 닫은 날도 없어 목록을 따로 받는다. `gh api`는 JSON을 읽기만 하는 GET이라 쓰기 범위는 그대로다.

### 1.2 추천은 5순위까지다 — #12

- 무엇을: 프롬프트가 순서에 드는 이슈를 전부 패키지에 넣게 해 claude가 이슈를 몽땅 쪼개고, 화면은 5장만 펼쳐 나머지를 "그 외 N개"로 접고, 검사는 패키지에 없는 이슈마다 "어느 패키지에도 없음" 경고를 단다 → 제안은 패키지 5개까지. claude는 열린 이슈를 전부 읽고 급한 순서로 5칸을 채우고, 못 들어간 이슈는 대기로 경고 없이 남는다. "그 외 N개" 접기와 "어느 패키지에도 없음" 경고가 없어진다. 크기 5 상한 · 중복 · 모르는 이슈 · 사슬 검사는 그대로이고, 막히는 이슈가 패키지에 있는데 막는 이슈가 어느 패키지에도 없으면 사슬 경고다. **`docs/SPEC.md` 후보 순서 절(패키지 검사) · 제안 절(출력) · 화면 절(카드 접기)이 바뀐다.** `docs/design.md`의 6순위 이하 접기 문장도 고친다.
- 어떻게: 프롬프트 규칙 4를 "패키지는 5개까지, 급한 것부터 채우고 나머지는 넣지 않는다"로 바꾸고 스키마에 `maxItems: 5`. 그래도 넘치면 순위 앞 5개만 남기고 로그에 한 줄. 검사에서 `missing`을 빼고 사슬 검사를 넓힌다. 화면은 접기를 지운다.
- 끝(SC-2): [제안]을 누르면 카드가 5장 이하이고 "그 외 N개" · "어느 패키지에도 없음"이 없다 — `bun test`(가짜 claude가 7개를 주면 5개 저장 · 빠진 이슈 경고 없음 · 막는 쪽이 패키지 밖이면 사슬 경고) · 사용자 육안(카드 수 · 접기 없음). 실데이터 열린 이슈가 5개라 넘치는 경우는 테스트가 근거다.
- 왜 이렇게: 스키마 제한만 믿지 않고 코드가 한 번 더 자르는 것은 LLM 출력을 검사하는 원칙 그대로다. 사슬 검사를 넓히지 않으면 5개 제한 때문에 막는 쪽이 통째로 빠져도 조용하다.

### 1.3 안 뽑힌 추천은 순서를 지킨다 — #14

- 무엇을: [제안]마다 백지에서 다시 짜 받아둔 순위가 흔들리고, 사이클에 들어가 마일스톤이 붙은 이슈도 열려 있는 한 후보에 섞인다 → 제안은 같은 레포의 직전 제안(상태 ok)에서 이어진다. **진행 중**(마일스톤이 붙은 열린 이슈)은 후보 순서 · 프롬프트 · 패키지에서 빠지고 그래프에는 남는다. **뽑힘**은 직전 패키지의 이슈 중 지금 닫혔거나 마일스톤이 붙은 것. **유지**는 뽑힌 이슈가 없는 직전 패키지로, 이름 · 이슈를 그대로 들고 순서대로 앞으로 당겨진다. **풀림**은 일부만 뽑힌 패키지의 남은 이슈로 대기로 돌아간다. **새 이슈**는 직전 제안 때 없던 것, **바뀐 이슈**는 제목이나 본문이 달라진 것. 규칙: (1) 유지 패키지끼리 순서를 바꾸지 않고 남는 뒤 칸은 claude가 대기 · 풀린 · 새 이슈로 채운다. (2) 새 · 바뀐 이슈를 담은 패키지만 급할 때 유지 패키지를 앞지르고 "앞지름" 표시와 이유 한 줄이 붙는다. 바뀐 이슈는 원래 패키지에 남고 패키지째 앞지른다. (3) 새 이슈는 크기 5를 넘지 않으면 유지 패키지에 합류하고 "＋합류 #n"이 붙는다. (4) 선이 바뀌어 유지 순서가 사슬을 어기면 코드가 순서를 고치고 "선 때문에 이동"을 붙인다. 막는 이슈를 대기에서 끌어와 앞에 끼운 패키지도 이 표시로 허용한다. (5) 앞지름으로 5칸 밖에 밀린 유지 패키지는 풀린다. (6) 표시 없이 유지 순서가 바뀜 · 유지 패키지에서 이슈가 빠지거나 새 이슈 아닌 것이 낌 · 새 · 바뀐 이슈 없이 앞지름 · 칸이 남는데 유지 패키지가 사라짐은 경고다. (7) 직전 제안이 없거나 옛 모양이면 지금처럼 백지에서 짜고 표시가 없다. **`docs/SPEC.md` 후보 순서 절(진행 중 제외)과 제안 절(이어가기 · 표시 · 경고)이 바뀐다.**
- 어떻게: 제안에 그때 순서에 든 이슈마다 제목 · 본문 해시 스냅샷을 함께 저장한다. 뽑힘 · 유지 · 풀림 · 새 · 바뀐 판정과 선 때문에 고친 유지 순서는 코드가 순수 함수로 먼저 계산한다. 프롬프트에 "직전 제안에서 이어지는 것" 절(유지 순서 K1… · 풀린 · 새 · 바뀐 · 대기 이슈 · 규칙)을 더하고, 출력 패키지마다 유지한 패키지 키와 앞지른 이유를 받는다. 표시는 claude 말이 아니라 코드가 출력과 직전 제안을 비교해 붙이고, claude는 이유 문장만 준다. 카드에 표시 뱃지 셋과 이유 줄을 단다.
- 끝(SC-3): 규칙마다 가짜 claude 시나리오 — 1순위가 마일스톤에 들어가면 2~5순위가 1~4로 당겨짐 · 일부 뽑힌 패키지의 남은 이슈가 풀림 · 새 이슈가 끼어들면 앞지름 · 합류하면 ＋합류 · 새 선이 순서를 어기면 선 때문에 이동 · 표시 없는 순서 변경은 경고 · 마일스톤 붙은 이슈는 프롬프트에 없음 — `bun test`. 사용자 육안 — [제안] → GitHub에서 대기 이슈 본문에 급한 이유를 적음 → [새로고침] → [제안] → 카드에 표시가 그려진다. 실데이터 대기 이슈가 둘뿐이라 규칙의 근거는 테스트다.
- 왜 이렇게: "유지해 달라"고만 하면 지켰는지 알 수 없어 코드가 비교 · 검사하고 claude는 급함 · 합류 · 이름 · 이유만 판단한다. 유지 패키지를 코드가 박고 빈 칸만 채우게 하는 길은 보장이 가장 세지만 급할 때 앞지르는 판단이 들어갈 자리가 없어 버렸다.

제외: 그래프에서 진행 중 이슈를 구분해 그리기. 시각 문자열 형식(#15). claude가 선을 긋는 것(#11).
