## 1. 범위

화면이 고른 레포 하나만 보여 패키지가 곧 그 레포의 `/cycle:start` 묶음이 되고, claude 호출이 opus로 돌며 도는 동안 무엇을 하는지가 서버 터미널과 화면 로그 패널에 한 줄씩 흐른다.

### 1.1 레포 선택 — #9

- 무엇을: 헤더 레포 칩은 표시만 하고, 이슈 · 선 API와 제안이 모든 레포를 섞는다. 다른 레포 이슈끼리 선이 그어지고, `proposals`에 레포 열이 없어 마지막 제안이 전체에 하나다 → 칩을 누르면 그 레포가 선택되고 그래프 · 상세 · 패키지가 그 레포 것만 보인다. 고른 레포는 다시 켜도 유지되고, 처음이면 첫 레포, 레포를 추가하면 그 레포로 넘어간다. 다른 레포 이슈끼리의 선은 서버가 거부한다. [제안]은 고른 레포의 이슈로만 돌고 레포마다 따로 저장되어, 레포를 바꾸면 그 레포의 마지막 제안이 보인다. 새로고침은 지금처럼 모든 레포를 동기화한다. **`docs/SPEC.md` 의존 선 절의 "레포를 넘나드는 선을 허용한다"가 금지로, 제안 절의 "마지막 것만"이 레포마다로, 화면 절 헤더가 레포 선택으로 바뀐다.**
- 어떻게: 서버는 이슈 · 선 · 제안 · 최근 제안 API에 레포 인자를 더하고, 마이그레이션 004로 `proposals.repo_id`를 넣어 기존 제안은 담긴 이슈의 레포로 채운다. 프론트는 store에 선택 레포를 두어 localStorage에 저장하고 Header 칩을 버튼으로 바꾼다.
- 끝(SC-1): `bun test server/deps server/propose server/app`로 다른 레포 선 거부 · 이슈 · 선 API의 레포 필터 · 프롬프트에 다른 레포 이슈 없음 · 레포별 최근 제안 — `bun test`. 사용자 육안(레포 둘 등록) — 칩을 누르면 그래프 · 패키지가 바뀌고, 브라우저를 새로고침해도 고른 레포가 유지되고, 상세의 "막는 이슈 추가" 목록에 그 레포 이슈만 나온다.
- 왜 이렇게: 사이클 · 마일스톤이 레포 안에서만 돌아 패키지도 레포 단위여야 `/cycle:start`에 넣을 수 있다. 선택 레포는 로컬 혼자 쓰는 앱이라 테이블 대신 localStorage에 둔다.

### 1.2 opus 호출과 진행 로그 — #10

- 무엇을: `claude -p`에 모델 지정이 없어 사용자 기본 모델로 돌고, `--output-format json`이라 끝날 때 결과만 온다. 도는 동안 서버도 화면도 말이 없다 → `--model opus`로 돈다. 호출마다 입력 크기 · 시작과 실제 모델 · 응답 받는 중 · 응답 끝(비용 · 소요 시간) · 검증(패키지 수 · 경고 수) · 저장 줄이, 재시도 · 실패면 그 줄도 서버 터미널에 찍히고 같은 줄이 화면 하단 오른쪽 로그 패널에 실시간으로 흐른다. opus로 실제 제안을 돌린 비용 · 시간이 `docs/SPEC.md` 제안 절에 적히고, 호출당 예산 상한은 실측을 보고 정한다. **`docs/SPEC.md` 제안 절의 `claude -p` 옵션 · 비용 줄, 화면 절(로그 패널), API 줄(`GET /api/logs`)이 바뀐다.**
- 어떻게: `server/llm/claude.ts`가 `--output-format stream-json --verbose`로 줄마다 이벤트를 읽어 시작 이벤트에서 모델, 결과 이벤트에서 구조화 출력 · 비용을 뽑는다. 파싱은 순수 함수로 뗀다. 서버 안 로그 버스가 줄을 터미널에 찍고 구독자에게 뿌리며 최근 200줄을 든다. `GET /api/logs`는 SSE로 핑을 보내 유휴 제한을 피하고, 열면 최근 줄부터 준다. `propose`는 로거를 주입받는다. 화면 패널이 막히면 서버 터미널만으로 줄인다(사용자 합의).
- 끝(SC-2): `bun test server/llm server/propose`로 가짜 stream 출력에서 모델 · 구조화 출력 · 비용 추출 · 깨진 줄이 섞여도 결과 이벤트를 찾음 · 제안 한 번에 로그 줄이 입력 → 시작 → 응답 끝 → 검증 → 저장 순서로 쌓임 · 재시도 줄 — `bun test`. 사용자 육안 — [제안]을 누르면 로그 패널에 줄이 몇 초 간격으로 흐르고 터미널에도 같은 줄이 찍히고 "claude 시작" 줄의 모델이 opus다. 실측 비용 · 시간이 `docs/SPEC.md` 제안 절에 적혀 있다.
- 왜 이렇게: stream-json은 claude가 실제 모델을 직접 알려주고 도는 중이라는 신호도 여기서만 나온다. 서버 → 화면 한 방향이라 SSE로 충분하다. 폴링은 지연이 생기고 WebSocket은 이 크기에 과하다.

제외: gh 동기화 · 라벨 반영의 로그(이슈가 claude 호출에 한정). 시각 문자열 형식.
