## 1. 범위

이슈 사이의 "막는다" 관계를 로컬에 긋고, 그 관계가 토폴로지 그래프로 보인다. 왼쪽 목록은 그래프로 바뀐다.

### 1.1 의존 선 — #4

- 무엇을: 이슈 사이 관계를 적을 곳이 없음 → `deps` 테이블이 002 마이그레이션으로 생긴다(`blocker_id` · `blocked_id` · `created_at`, 둘이 합쳐 유일, 자기 자신 금지, 이슈가 지워지면 같이 지워짐). API 셋(`GET /api/deps` · `POST /api/deps` · `DELETE /api/deps/:blocker/:blocked`)이 붙는다. 상세 패널에 "이 이슈를 막는 것" 절이 생겨 열린 이슈 중 골라 추가하고 ×로 지운다. "이 이슈가 막는 것"은 표시만. 앱을 다시 켜도 남는다.
- 어떻게: 서버는 `server/deps/` 모듈 하나(add · remove · list)와 마이그레이션 한 장, 라우트 셋. 자기 자신 금지는 DB `check`와 서버 검사 둘 다. 프론트는 store에 `deps` 배열을 얹고 IssueDetail에 편집 UI. 레포를 넘나드는 것은 FK가 `issues.id`라 따로 할 것이 없다.
- 끝(SC-1): `bun test server/deps`로 추가 · 목록 · 삭제 · 자기 자신 거부 · 같은 선 두 번은 하나 — `bun test`. 사용자 육안 — 상세에서 막는 이슈를 하나 추가하면 칩이 생기고, 서버를 껐다 켜도 그대로 있고, ×를 누르면 사라진다.
- 왜 이렇게: `docs/design.md` "의존 관계는 로컬에만" · 데이터 모델 그대로. 방향은 blocker → blocked. 상세 패널에서 긋는 것을 먼저 하는 이유는 그래프 드래그가 없어도 선을 만들 수 있어야 1.2를 육안으로 볼 수 있어서.

### 1.2 그래프 — #5

- 무엇을: 왼쪽 이슈 목록 → @xyflow/svelte 그래프. 노드는 이슈 카드(번호 · 제목 · 라벨 뱃지), 선은 blocker → blocked 화살표. 좌표는 dagre가 위에서 아래로. 열린 이슈만 그리고 닫힌 이슈에 걸린 선은 그리지 않는다. 순환이 있으면 그 선들이 빨강. 노드 클릭 → 아래 상세. 노드 핸들을 드래그해 선을 그으면 `POST /api/deps`로 저장되어 상세 패널 칩에도 뜬다. 목록 컴포넌트는 없앤다. 선 없는 이슈도 고립 노드로 보이므로 목록이 중복이다.
- 어떻게: 의존성 `@xyflow/svelte` · `@dagrejs/dagre` 추가. 순환 검출은 서버 쪽 순수 모듈 `server/graph/`에 두고 프론트가 런타임 import한다(플레인 TS). 레이아웃 변환(이슈 + 선 → 노드 · 엣지 · 좌표)은 `web/src/lib/layout.ts`. 컴포넌트는 `Graph.svelte`와 커스텀 노드 `IssueNode.svelte`. `IssueList.svelte` 삭제.
- 끝(SC-2): `bun test server/graph`로 순환 검출(없음 · 2개짜리 · 3개짜리 · 순환 아닌 다이아몬드) — `bun test`. `bun run check` 에러 0. 사용자 육안 — ① 이슈 8개가 카드 노드로 보인다 ② 1.1에서 그은 선이 화살표로, 막는 쪽이 위 ③ 노드를 클릭하면 아래 상세 ④ 핸들 드래그로 선을 그으면 상세 칩에도 생긴다 ⑤ 서로 막게 만들면 두 선이 빨강.
- 왜 이렇게: `docs/design.md` 그래프 결정(xyflow + dagre). 순환 검출을 서버 순수 모듈에 두는 것은 #6(후보 순서)이 같은 것을 쓰고 `bun test`로 검증되기 때문. **`docs/SPEC.md` 화면 절의 "왼쪽 열린 이슈 목록"이 "왼쪽 그래프"로 바뀐다. 목록 행 규칙 줄은 없어진다.**

제외: 후보 순서(#6) · 제안(#7). 순환 검출만 이번에 한다.
